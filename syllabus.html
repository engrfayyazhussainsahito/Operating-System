Syllabus

Operating Systems

Level Undergraduate, second or third year. Duration 16 weeks. Format Two lectures and one lab per week. Credit hours 3 plus lab.

Course description

Operating systems manage the hardware that every other program depends on. This course explains how processes, threads, memory, storage and protection are designed, why the designs look the way they do, and how to measure them. Theory is paired with C programs on Linux and with browser simulators so that each algorithm can be run, traced and broken.

Prerequisites

  • Programming in C (pointers, structs, dynamic memory)
  • Data structures: lists, queues, trees, hash tables
  • Computer organisation: registers, memory, instruction cycle
  • Comfort with a Linux shell

Learning outcomes

  1. Explain the roles of an operating system and trace a system call across the user and kernel boundary.
  2. Model processes and threads, and write C programs that create and coordinate them with fork, exec, wait, pipes and pthreads.
  3. Evaluate CPU scheduling policies by computing waiting, turnaround and response times.
  4. Find race conditions and repair them with locks, semaphores, condition variables and monitors.
  5. Analyse deadlock with resource allocation graphs and decide safety with the Banker's algorithm.
  6. Translate addresses through paging, segmentation and multi-level page tables, and compute effective access time.
  7. Simulate page replacement policies and diagnose thrashing with the working set model.
  8. Describe disk scheduling, RAID, file system layouts, caching and journaling, and compute their costs.
  9. Reason about protection, security mechanisms, virtual machines and containers.

Tools and software

  • gcc, make and gdb on Linux or WSL
  • strace, ltrace, perf (optional) and valgrind
  • A text editor and Git
  • Optional: xv6-riscv with QEMU for the final project

Textbooks and references

Primary. Arpaci-Dusseau and Arpaci-Dusseau, Operating Systems: Three Easy Pieces (free online). Silberschatz, Galvin and Gagne, Operating System Concepts.

Supplementary. Tanenbaum and Bos, Modern Operating Systems. Kerrisk, The Linux Programming Interface. Love, Linux Kernel Development.

Weekly schedule

Phase I: Foundations

Week 1: Introduction, OS Structure and System Calls

Topics

  • What an OS is: resource manager, abstraction layer, kernel versus OS
  • Hardware recap: CPU modes, interrupts, traps, DMA and the memory hierarchy
  • Dual-mode operation and the system call path from user space to the kernel
  • APIs versus system calls (POSIX, libc wrappers) and tracing with strace
  • OS structures (monolithic, layered, microkernel, hybrid, modules, unikernel) and booting

Readings Silberschatz Ch. 1 and Ch. 2; Tanenbaum MOS Ch. 1; OSTEP chapters "Introduction" and "A Dialogue on the Book"

Lab Use strace to watch a small C program talk to the kernel, then write programs that call open, read and write directly and count their system calls.

Week 2: Processes

Topics

  • Program versus process, and the memory layout of a process
  • Process states and the process control block (PCB)
  • Context switching and its cost
  • Process creation and termination: fork, exec, wait, zombies and orphans
  • Process queues and the long-, medium- and short-term schedulers

Readings Silberschatz Ch. 3 (Processes); Tanenbaum MOS Sec. 2.1; OSTEP chapters "The Abstraction: The Process", "Interlude: Process API" and "Mechanism: Limited Direct Execution"

Lab Build a tiny Unix shell in C that reads a command, forks, execs it and waits for it.

Week 3: Threads and Interprocess Communication

Topics

  • Threads versus processes: what is shared and what is private
  • POSIX threads: creating, joining and passing arguments safely
  • User-level and kernel-level threads, and the multithreading models
  • Parallelism, concurrency and Amdahl's law
  • Interprocess communication: shared memory, message passing, pipes and signals
  • Process trees built with fork loops

Readings Silberschatz Ch. 4 (Threads and Concurrency) and Sec. 3.4 to 3.6 (IPC); Tanenbaum MOS Sec. 2.2 and 2.3.1; OSTEP chapters "Concurrency: An Introduction" and "Interlude: Thread API"

Lab Parallelize an array sum with pthreads, measure the speedup on your machine and compare it with Amdahl's law.

Week 4: CPU Scheduling

Topics

  • CPU and I/O bursts, the dispatcher, and the waiting, turnaround and response metrics
  • FCFS, SJF and SRTF compared on one worked example
  • Round robin, priority scheduling, aging and multilevel feedback queues
  • Linux CFS: weights, nice values and virtual runtime
  • Real-time scheduling: rate-monotonic, EDF and the Linux real-time classes

Readings Silberschatz Ch. 5; Tanenbaum MOS Sec. 2.5; OSTEP chapters Scheduling Introduction, The Multi-Level Feedback Queue, Scheduling Proportional Share, Multiprocessor Scheduling

Lab Build a tick-by-tick scheduling simulator in C and check its output against hand-drawn Gantt charts.

Due Assignment 1 (shell and fork/exec)

Phase II: Concurrency and Deadlocks

Week 5: Synchronization I

Topics

  • Race conditions and the counter++ interleaving
  • The critical section problem: mutual exclusion, progress, bounded waiting
  • Peterson's algorithm, atomic instructions and memory barriers
  • Spinlocks versus mutexes, and priority inversion
  • Semaphores and POSIX mutexes, semaphores and condition variables

Readings Silberschatz Ch. 6; Tanenbaum MOS Sec. 2.3; OSTEP chapters Locks, Condition Variables, Semaphores, Common Concurrency Problems

Lab Fix a racy shared counter in C three ways (mutex, atomic spinlock, semaphore) and time each version.

Week 6: Synchronization II

Topics

  • The bounded buffer (producer-consumer) problem solved with semaphores
  • Monitors, Mesa versus Hoare semantics, and condition variables
  • The readers-writers problem and its starvation trade-offs
  • The dining philosophers problem: deadlock, ordering and limiting solutions
  • Midterm review: a ten-item checklist covering Weeks 1 to 7

Readings Silberschatz Ch. 6 (monitors) and Ch. 7 (classic problems); Tanenbaum MOS Ch. 2 (monitors, classical IPC problems); OSTEP chapters Semaphores, Condition Variables, Common Concurrency Problems

Lab Measure writer starvation under reader-preferring and writer-preferring read-write locks, and compile and run every classic solution from this chapter.

Week 7: Deadlocks

Topics

  • Deadlock defined, the four Coffman conditions and resource-allocation graphs
  • Prevention: breaking one condition, with lock ordering as the practical case
  • Avoidance: safe states and the Banker's algorithm traced on a five-process example
  • Detection with wait-for graphs and the detection algorithm, plus recovery options
  • Deadlock, livelock and starvation compared

Readings Silberschatz Ch. 8; Tanenbaum MOS Ch. 6; OSTEP chapter Common Concurrency Problems (deadlock section)

Lab Reproduce a two-lock deadlock in C, then remove it with lock ordering and with trylock and back-off.

Due Assignment 2 (threads and synchronization)

Phase III: Memory

Week 8: Main Memory

Topics

  • Logical versus physical addresses, the MMU and base and limit protection
  • Contiguous allocation: first fit, best fit, worst fit and fragmentation
  • Paging: page tables, address translation and page table size
  • TLBs, effective access time and multilevel, hashed and inverted page tables
  • Segmentation and the Midterm covering Weeks 1 to 7

Readings Silberschatz Ch. 9; Tanenbaum MOS Ch. 3 (Sec. 3.1 to 3.3); OSTEP chapters Address Spaces, Address Translation, Segmentation, Free Space Management, Paging, TLBs, Multi-level Page Tables

Lab Simulate first, best and worst fit on a list of holes in C and compare how many requests each places and how much memory stays fragmented.

Due Project proposal

Exam Midterm covering Weeks 1 to 7

Week 9: Virtual Memory

Topics

  • Why virtual memory: larger-than-RAM programs, sharing, isolation
  • Demand paging, the valid/invalid bit and page-fault handling
  • Effective access time with a page-fault rate
  • Copy-on-write, fork and memory-mapped files
  • Kernel allocators (buddy, slab), user-level malloc, page sizes and TLB reach

Readings Silberschatz Ch. 10 (Virtual Memory, sections 10.1 to 10.4 and 10.8); OSTEP chapters "Beyond Physical Memory: Mechanisms" and "The Linux Virtual Memory System"; Tanenbaum Ch. 3.3 (Virtual Memory)

Lab Write C programs that mmap a file, observe copy-on-write after fork, and measure the cost of a page fault.

Week 10: Page Replacement, Frame Allocation and Thrashing

Topics

  • Page replacement: dirty bit, reference strings, FIFO, OPT and LRU with worked traces
  • Belady's anomaly and stack algorithms
  • LRU approximations: reference bits, aging, second chance (Clock) and enhanced Clock
  • Frame allocation: minimum frames, equal, proportional and priority; global versus local replacement
  • Thrashing, the working set model and page-fault frequency; Linux reclaim and the OOM killer

Readings Silberschatz Ch. 10 (Virtual Memory, sections 10.4 to 10.7); OSTEP chapter "Beyond Physical Memory: Policies"; Tanenbaum Ch. 3.4 (Page Replacement Algorithms) and 3.5 (Design Issues for Paging Systems)

Lab Build a page replacement simulator in C, compute working-set sizes, draw fault-rate curves for local and random traces, and watch a page-fault-frequency controller resize a process.

Due Assignment 3 (memory manager or page replacement simulator)

Phase IV: Storage, Protection and Modern Systems

Week 11: Mass Storage: Disks, SSDs, Scheduling and RAID

Topics

  • Hard disk geometry and access time: seek, rotational latency and transfer
  • Solid-state drives: flash pages and blocks, the flash translation layer, garbage collection, wear leveling and write amplification
  • Disk scheduling: FCFS, SSTF, SCAN, C-SCAN, LOOK and C-LOOK
  • RAID levels 0, 1, 5, 6 and 10: striping, mirroring, parity, capacity and the small-write penalty
  • Disk management: partitions, formatting, bad blocks and swap space

Readings Silberschatz Ch. 11 (Mass-Storage Structure); OSTEP chapters "Hard Disk Drives", "Redundant Arrays of Inexpensive Disks (RAIDs)" and "Flash-based SSDs"; Tanenbaum Ch. 5.4 (Disks)

Lab Compute disk access times, implement and compare the disk scheduling algorithms, simulate a flash translation layer to measure write amplification, and verify RAID capacity and XOR parity arithmetic in C.

Week 12: File Systems I: Interface and Implementation

Topics

  • Files, attributes, directories, paths and the open-file tables
  • Allocation methods: contiguous, linked, FAT and indexed
  • Unix inodes: direct and indirect pointers, offset to block mapping, maximum file size
  • Free-space management with bitmaps and free lists
  • Hard links, symbolic links, mounting and the VFS layer

Readings Silberschatz Ch. 13 (File-System Interface) and Ch. 14 (File-System Implementation); Tanenbaum Ch. 4 (File Systems); OSTEP chapters "Files and Directories", "File System Implementation" and "Locality and The Fast File System"

Lab Use stat and readdir from C to inspect inodes and link counts, observe shared file offsets after fork, and write a block-map calculator that turns a byte offset into a path through an inode.

Week 13: File Systems II: Journaling, Caching and the I/O Subsystem

Topics

  • The crash consistency problem and fsck
  • Journaling (write-ahead logging), ext3/ext4 modes, copy-on-write and log-structured file systems
  • Buffer and page cache, write-back vs write-through, read-ahead, fsync and durability
  • VFS layer and network file systems (NFS and statelessness)
  • Polling, interrupts, DMA, memory-mapped I/O, drivers and kernel I/O schedulers
  • Blocking, non-blocking and asynchronous I/O (select, poll, epoll, io_uring)

Readings Silberschatz Ch. 12 (I/O Systems) and Ch. 14 to 15 (File-System Implementation and Internals); Tanenbaum Ch. 5 (Input/Output); OSTEP chapters Crash Consistency: FSCK and Journaling, Log-structured File Systems, I/O Devices, Sun's Network File System

Lab Measure write() against write()+fsync() latency in C, build a toy write-ahead log in Python with a simulated crash and recovery, and write a non-blocking echo server with epoll.

Week 14: Protection and Security

Topics

  • Protection domains, privilege rings and the access matrix
  • ACLs versus capabilities, and how revocation differs
  • Unix permissions: octal and symbolic modes, directories, setuid, setgid, sticky bit and umask
  • Least privilege, dropping privilege and Linux capabilities
  • Authentication basics and memory-safety defenses (canaries, NX, ASLR)
  • seccomp sandboxing, the confused deputy and TOCTOU races

Readings Silberschatz Ch. 16 (Security) and Ch. 17 (Protection); Tanenbaum Ch. 9 (Security); OSTEP chapters Introduction to Operating System Security, Authentication and Access Control

Lab Write C programs that inspect permission bits, show the effect of umask, drop setuid privilege, open files without a check-then-use race and install a seccomp filter, then observe ASLR, canaries and NX on a real binary.

Due Assignment 4 (file system or disk scheduler simulator)

Week 15: Virtualization, Containers and Case Studies: Linux and Windows

Topics

  • Hypervisors (type 1 and type 2), trap-and-emulate and the Popek and Goldberg conditions
  • Binary translation, paravirtualization and hardware support (VT-x, AMD-V, nested page tables)
  • Linux namespaces and cgroups, and containers versus virtual machines
  • Linux case study: the task model, CFS and EEVDF, memory management, VFS
  • Windows case study: NT executive, objects and handles, priority scheduling, memory manager, NTFS overview

Readings Silberschatz Ch. 18 (Virtual Machines), Ch. 20 (The Linux System) and Ch. 21 (Windows 10); Tanenbaum Ch. 7 (Virtualization and the Cloud), Ch. 10 (Linux) and Ch. 11 (Windows); OSTEP appendix on Virtual Machine Monitors and chapter Scheduling: Proportional Share

Lab Observe namespaces with unshare and clone(), limit a process group with cgroup v2, list the tasks of a threaded process, simulate CFS weights in C and detect a hypervisor with CPUID.

Week 16: Review, Projects and Final Exam

Topics

  • Phase-by-phase review map of Weeks 1 to 15
  • Cumulative cheat sheet of equations, algorithms and conventions
  • Debugging checklist for races, deadlocks, leaks, zombies and permissions
  • Final project types, milestones and evaluation
  • Next steps: reading xv6 and Linux source, kernels to study, careers
  • A practice final exam covering all 16 weeks

Readings Silberschatz Ch. 1 (Introduction) and the summaries at the end of each chapter; Tanenbaum Ch. 1 (Introduction); OSTEP "Dialogue on the Book" and the concluding dialogues of each of its three parts

Lab Build and run a small C program that combines fork, pipe, threads and mmap, then check it with ThreadSanitizer, AddressSanitizer and Valgrind.

Due Final project report

Exam Final exam (cumulative)

Final project guidelines

  • Team size. One to three students.
  • Project types. Choose one: a kernel feature in xv6 or a Linux module, a simulator with an evaluation, or a measured study of a real OS behaviour.
  • Milestones. Proposal in Week 8, instructor feedback in Week 12, report and code in Week 16.
  • Evaluation. Correctness, depth of measurement, clarity of the write-up.

Course policies

  • Attendance and participation. Labs are graded on observations, so attend or submit the write-up.
  • Late work. Ten percent per day, up to three days.
  • Academic integrity. Discuss ideas freely, write your own code, cite sources, disclose AI assistance.
  • Compute access. Any Linux machine, WSL or a free cloud shell is enough.
  • Accessibility. The site works with a keyboard and supports light and dark themes. Tell the instructor about any barrier.
