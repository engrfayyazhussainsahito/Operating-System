Reference

Glossary

242 terms, each linked to the week that defines it.

ABCDEFGHIJKLMNOPRSTUVWXZ

A

Abstraction Week 1
A simple, idealised concept the OS builds on top of messy hardware, such as a process, a file or a socket.
Access control list Week 14
A column of the access matrix stored with an object, listing which subjects may perform which operations on it. Unix permission bits are a compressed three-entry ACL.
Access matrix Week 14
A model with subjects as rows, objects as columns and sets of rights as entries, used to reason about protection independently of any system.
Address space Week 2
The private range of memory addresses a process sees, usually organized into text, data and bss, heap and stack regions.
AddressSanitizer Week 16
A compiler-based tool, enabled with -fsanitize=address, that places guard zones around allocations to detect out-of-bounds accesses, use-after-free and, on Linux, memory leaks.
Aging Week 4
Gradually raising the priority of a job the longer it waits, so that even the lowest priority job eventually runs and starvation is avoided.
Amdahl's law Week 3
The speedup on N cores is 1 / (S + (1 - S) / N) for serial fraction S, so the speedup can never exceed 1 / S.
Anonymous mapping Week 16
A mmap region not backed by a file, created with MAP_ANONYMOUS and initially filled with zeros; with MAP_SHARED it can be shared with child processes after fork.
API Week 1
Application programming interface, a set of documented functions such as those in POSIX, which libc wrappers translate into system calls.
ASLR Week 14
Address space layout randomization: the kernel places the stack, heap, libraries and position-independent executables at random addresses on each run, so an attacker must guess addresses.
Asymmetric solution Week 6
A dining philosophers fix in which odd-numbered philosophers pick up the left fork first and even-numbered ones the right fork first, which breaks the cycle of waiting.

B

Backtrace Week 16
The chain of function calls active at a given moment, printed by a debugger with the bt command, used to locate where a crash or a hang occurred.
Banker's algorithm Week 7
A deadlock avoidance method using Available, Max, Allocation and Need = Max minus Allocation. A request is granted only if pretending to grant it leaves the system in a safe state, checked by the safety algorithm.
Base and limit registers Week 8
The simplest MMU: the CPU compares each logical address with the limit and, if it is smaller, adds the base. Together they provide relocation and protection.
Belady's anomaly Week 10
The situation in which giving a process more frames increases its page faults for the same reference string. FIFO can show it (9 faults with 3 frames, 10 with 4 on the standard string), while LRU and OPT cannot.
Best fit Week 8
A hole-selection policy that takes the smallest hole big enough for the request. It scans the whole list and leaves the smallest leftover.
Binary translation Week 15
A virtualization technique in which the hypervisor rewrites guest kernel code before running it, replacing problematic instructions with safe sequences.
Bitmap Week 12
A free-space structure with one bit per disk block, marking it used or free. It is compact and makes finding runs of consecutive free blocks easy.
Bootstrap Week 1
The process of getting an OS running after power-on, passing control from firmware (BIOS or UEFI) to a bootloader, then to the kernel, then to the first user process.
Bounded buffer Week 6
A shared buffer of fixed capacity N between producers and consumers. Producers must wait when it is full, consumers must wait when it is empty, and only one thread may change its indices at a time.
Bounded waiting Week 5
The requirement that there is a limit on how many times others may enter their critical sections after a thread has requested entry and before it is granted, so nobody starves.
Bss Week 2
The part of a process's static data that is initialized to zero; the program file records only its size, not its contents.
Buddy system Week 9
An allocator for physically contiguous memory in power-of-two blocks that splits larger blocks in half and merges a freed block with its buddy at address a XOR size.

C

Capability Week 14
An unforgeable token naming an object and the rights of its holder, stored as a row of the access matrix. A Unix file descriptor is a capability in miniature.
Cgroup Week 15
A control group: a node in a tree of process groups to which the kernel attaches resource limits and shares, such as cpu.max, memory.max and pids.max.
Checkpoint Week 13
The step of writing the logged blocks of a committed transaction to their final locations in the main file system.
Circular wait Week 7
The deadlock condition that there is a cycle of threads in which each waits for a resource held by the next. It is the condition most often attacked by prevention.
Clock algorithm Week 10
A circular implementation of second chance, in which a hand sweeps the frames. A page with reference bit 1 has the bit cleared and is skipped, and the first page found with bit 0 is evicted.
Compaction Week 8
Sliding all processes to one end of memory so the holes merge into one. It needs run-time relocation and is expensive because it copies memory.
Compare-and-swap Week 5
An atomic instruction that replaces a word with a new value only if it currently equals an expected value, and reports whether it did.
Concurrency Week 3
The structure of a program in which several tasks are in progress during overlapping time periods, even if only one runs at any instant.
Condition variable Week 6
A queue inside a monitor with wait and signal operations, on which a thread sleeps until a predicate about the shared data becomes true. In C it is used together with a mutex.
Container Week 15
A set of processes that run on the shared host kernel inside chosen namespaces and a cgroup, usually with a restricted root file system and reduced privileges. It is not a separate kernel.
Context switch Week 2
Saving the context of the running process into its PCB and loading the saved context of another so the CPU changes processes; it is pure overhead.
Contiguous allocation Week 12
An allocation method in which each file occupies a run of consecutive blocks. It gives fast sequential and random access but suffers external fragmentation and makes growing files hard.
Convoy effect Week 4
The delay suffered by short jobs queued behind one long job under first-come, first-served scheduling.
Copy-on-write Week 9
A technique in which fork gives the child page tables pointing at the parent's frames, marked read-only, and a page is copied only when one process first writes it.
Copy-on-write file system Week 13
A file system that never overwrites live data, writing new blocks up the tree to a new root and then atomically switching the root pointer.
Core dump Week 16
A file the kernel writes when a process crashes, holding the memory image and registers of the process so that a debugger such as gdb can inspect the failure afterward.
CPU burst Week 4
A stretch of computing between waits for I/O. Most programs have many short bursts and a few long ones, which is why schedulers that favour short bursts keep interactive programs responsive.
Crash consistency Week 13
The property that after a crash and reboot a file system's on-disk metadata describe a valid file system, distinct from durability and atomicity.
Critical section Week 5
A stretch of code that accesses shared data and must not be executed by more than one thread at a time.
Cylinder Week 11
The set of tracks at the same arm position on all platter surfaces, which the heads can reach without moving the arm.

D

Data race Week 16
Two threads accessing the same memory location, at least one of them writing, with no synchronization ordering the accesses. It is narrower than a race condition, which is any result that depends on timing.
Deadlock Week 7
A situation in which every thread in a set is waiting for an event, typically the release of a resource, that only another thread in the set can cause, so the wait is permanent.
Deadlock detection Week 7
Letting deadlocks happen and finding them with a cycle search on a wait-for graph, or with a matrix algorithm that uses the current Request matrix when resources have several instances.
Deadlock prevention Week 7
Making at least one of the four necessary conditions impossible by design, for example by requiring all resources at once or by ordering resource acquisition.
Demand paging Week 9
Loading a page into memory only when it is first referenced, rather than loading the whole program at start-up.
Dining philosophers Week 6
A classic problem in which five philosophers need two adjacent forks to eat. If all take their left fork at once, every philosopher waits for a fork held by a neighbour, which is a deadlock.
Direct memory access (DMA) Week 1
A technique in which a controller moves a block of data between a device and memory on its own and raises one interrupt when done, leaving the CPU free.
Directory Week 12
A special file whose contents map names to inode numbers. Looking up a name means searching this table.
Dirty bit Week 10
A page-table bit that hardware sets whenever a page is written. A clean victim costs one disk read, while a dirty victim costs a write plus a read, so replacement prefers clean pages when the choice is close.
Disk access time Week 11
The time to read a block from a hard disk: seek time plus rotational latency plus transfer time, plus a small controller overhead.
Dispatch Week 2
The act of giving the CPU to the process chosen by the scheduler, moving it from Ready to Running.
Dispatcher Week 4
The part of the kernel that switches to the thread the scheduler chose: it performs the context switch, switches to user mode and jumps to the right instruction. Its delay is the dispatch latency.
Dual-mode operation Week 1
Hardware support in which a mode bit separates user mode from kernel mode, so that privileged instructions run only in kernel mode.

E

Earliest deadline first Week 4
Dynamic-priority real-time scheduling that always runs the job whose absolute deadline is nearest. For tasks with deadline equal to period it is optimal on one CPU, schedulable whenever utilization is at most 1.
Effective access time Week 9
The average memory access time including page faults, computed as (1 - p) times the memory access time plus p times the fault service time.
epoll Week 13
A Linux interface for I/O multiplexing in which descriptors are registered once and each wait returns only the ready ones.
exec Week 2
A family of calls (wrappers for execve) that replace the calling process's program with a new one while keeping its PID and open files; it returns only on error.
Exponential average Week 4
The prediction of the next CPU burst from history, tau(n+1) = alpha times t(n) plus (1 minus alpha) times tau(n), where t(n) is the last measured burst and tau(n) the previous prediction.
Extent Week 12
A pair (start block, length) describing a run of contiguous blocks. File systems such as ext4 and XFS store a file as a short list of extents instead of one pointer per block.
External fragmentation Week 8
Wasted memory between allocated blocks, where enough total free memory exists but no single hole is large enough. Contiguous allocation and segmentation suffer from it, and paging does not.

F

File Week 12
A named, persistent collection of related bytes managed by the OS. To the kernel it is an unstructured sequence of bytes, and any structure is imposed by the programs that use it.
File Allocation Table Week 12
A table at the start of a volume with one entry per block or cluster, holding the next block of the file, an end-of-file mark, or a free marker. Cached in memory, it makes following a chain cheap.
File descriptor Week 12
A small integer returned by open that indexes the process's descriptor table and refers to an open file entry. After open, read and write need no path.
File descriptor leak Week 16
A file descriptor that is opened but never closed. Repeated leaks exhaust the per-process limit and cause the error EMFILE, too many open files.
First fit Week 8
A hole-selection policy that takes the first hole big enough for the request. It is fast because the search stops early.
Flash translation layer Week 11
Firmware in an SSD that maps logical blocks to physical flash pages, writes new data to fresh pages like a log, and performs garbage collection, wear leveling and bad block management.
fork Week 2
The Unix system call that creates a child as a near copy of the caller, returning the child's PID to the parent and 0 to the child.
Fork loop Week 3
A loop that calls fork on every pass in every process, so n passes create 2 to the power n processes unless children break out.
Frame Week 8
A fixed-size block of physical memory, the same size as a page, into which any page can be placed.
fsck Week 13
A tool that scans the whole file system after an unclean shutdown and repairs inconsistencies, taking time proportional to the size of the disk.
fsync Week 13
A system call that writes a file's dirty data and metadata to stable storage and returns when the device reports completion, which a plain write does not guarantee.

G

Garbage collection Week 11
The SSD background process that picks a block with many stale pages, copies its remaining valid pages elsewhere and erases it, so the block can be written again. The copying adds extra flash writes.
Global replacement Week 10
Replacement in which a faulting process may choose its victim from any frame in the system, including frames owned by other processes. It usually gives higher throughput but lets one process's behaviour affect the others.

H

Handle Week 15
In Windows, a per-process table index that refers to a kernel object and records the access rights granted when it was opened.
Hard link Week 12
An additional directory entry for an existing inode, so several names refer to the same file. It works only within one file system, cannot be made to a directory, and the data survive until the last name is removed.
Heisenbug Week 16
A bug that changes or disappears when you try to observe it, for example by adding a print statement or running under a debugger. It usually indicates a race or uninitialized data.
Hoare semantics Week 6
Monitor semantics (signal and wait) in which the signaller hands the monitor to the woken thread and sleeps, so the awaited condition is guaranteed true on wake-up and an if test suffices.
Hold and wait Week 7
The deadlock condition that a thread holding at least one resource is waiting to acquire more.
Huge page Week 9
A much larger page, such as 2 MiB on x86-64, that increases TLB reach at the cost of more internal fragmentation.
Hypervisor Week 15
Software, also called a virtual machine monitor, that creates and runs virtual machines by multiplexing the real CPU, memory and devices among guest operating systems.

I

Indexed allocation Week 12
An allocation method in which an index block lists the data blocks of a file, so block k is simply index[k]. Multilevel indexes extend this to large files.
Indirect block Week 12
A block that holds a table of block pointers instead of file data. An inode uses single, double and triple indirect pointers, which with 4 KiB blocks and 4-byte pointers hold 1024 pointers per block.
Inode Week 12
The on-disk record that holds a file's attributes (type, size, owner, permissions, timestamps, link count) and its block pointers. It does not contain the file's name.
Internal fragmentation Week 8
Wasted memory inside an allocated block because memory is handed out in units larger than the request, such as the last page of a process, which wastes about half a page on average.
Interprocess communication Week 3
The mechanisms, mainly shared memory and message passing, by which separate processes exchange data and coordinate.
Interrupt Week 1
An asynchronous signal from hardware, such as a timer expiring or a disk finishing, that makes the CPU save its state and run an interrupt handler.
Inverted page table Week 8
A table with one entry per physical frame holding (process id, page number). It scales with RAM instead of with address spaces, but lookups need a search, usually through a hash table.
io_uring Week 13
A Linux completion-based asynchronous I/O interface using shared submission and completion ring buffers to submit many operations with few or no system calls.

J

Journaling Week 13
Write-ahead logging in which a file system records what it is about to do in a journal before doing it, so recovery time depends on journal size, not disk size.

K

Kernel Week 1
The core part of the operating system that runs with full hardware privilege at all times and that other software calls into.
Kernel-level thread Week 3
A thread known to and scheduled by the operating system, so a blocking call stops only that thread and several threads can run on different cores.

L

Limiting the diners Week 6
A cure for the dining philosophers deadlock: a counting semaphore initialized to N minus 1 lets at most four of five philosophers try to eat, which guarantees that at least one can get both forks.
Linked allocation Week 12
An allocation method in which each block holds a pointer to the next block of the file. It has no external fragmentation, but reaching logical block k takes k disk reads.
Linux capabilities Week 14
Roughly forty separate privileges, such as CAP_NET_BIND_SERVICE, into which root's all-or-nothing power is divided so a program can hold only what it needs.
Livelock Week 7
A situation in which threads keep running but make no progress, for example when two threads release and retry a lock at the same moment forever. Randomized back-off breaks the symmetry.
Local replacement Week 10
Replacement in which a faulting process may choose a victim only from its own frames. A process's fault rate then depends mostly on itself, but frames held by processes that do not need them can be wasted.
Locality Week 1
The tendency of programs to reuse data they just used (temporal) and data near it (spatial), which is why memory hierarchies and caches work.
Locality of reference Week 9
The tendency of programs to touch a small set of nearby or recently used pages repeatedly, which keeps page-fault rates extremely low.
Lock ordering Week 7
Giving every resource a unique number and always acquiring them in increasing order, which breaks circular wait at very low cost. A transfer function can lock the account with the lower address first.
Log-structured file system Week 13
A file system that buffers all writes into large segments appended sequentially to a log, needing an inode map and a cleaner to reclaim dead segments.
Logical address Week 8
The address a program generates, also called a virtual address. The MMU converts it to a physical address on every memory reference.
Logical block addressing Week 11
The interface in which a drive presents itself as a flat array of numbered blocks (block 0, 1, 2 and so on), hiding the physical geometry and bad-sector remapping from the OS.
Lost update Week 5
A race outcome in which two read-modify-write sequences overlap and one thread's write overwrites the other's, so an increment disappears.
LRU Week 10
Least recently used replacement, which evicts the page that was used longest ago, betting on temporal locality. It is usually close to OPT but needs per-reference bookkeeping that real hardware does not provide.

M

Master File Table Week 15
The NTFS structure that holds one record per file or directory, typically 1,024 bytes, made of attributes. Small files are stored inside the record and larger ones as lists of cluster runs.
Memory barrier Week 5
An instruction or ordering constraint that stops the compiler and processor from reordering memory operations across it, for example between a store and a later load.
Memory leak Week 16
Memory that was allocated and is still held but can no longer be used because the last pointer to it was lost, so a long-running program grows until memory runs out.
Memory management unit Week 8
The hardware that converts logical addresses to physical addresses on every memory reference and traps accesses outside the process's space.
Memory-mapped file Week 9
A file associated with a range of virtual addresses by mmap, so that touching memory page-faults the file's data in and reads and writes need no system calls.
Mesa semantics Week 6
Monitor semantics (signal and continue) in which the signaller keeps running and the woken thread only becomes ready. Signal is a hint, so the waiter must re-check its predicate in a while loop. POSIX threads, Java and C# use it.
Message passing Week 3
An IPC method where processes exchange discrete messages through the kernel using operations such as send and receive.
Microkernel Week 1
A kernel design that keeps only minimal services in kernel mode and runs file systems and drivers as user-mode servers that communicate by messages.
Monitor Week 6
A module that bundles shared data, the procedures that operate on it and a lock, so that at most one thread is active inside at any time. It also provides condition variables for waiting inside the monitor.
Monolithic kernel Week 1
A kernel design in which all major services run in kernel mode in one address space, which is fast but lets a faulty driver crash the system.
Mounting Week 12
Attaching the root of one file system to a directory (the mount point) of the existing tree, giving a single namespace across devices.
Multilevel feedback queue Week 4
A scheduler with several queues of different priority and quantum. New jobs enter the top queue, jobs that use a full quantum are demoted, and a periodic priority boost prevents starvation.
Multilevel page table Week 8
A page table that is itself paged, such as a two-level table with outer and inner tables of 1024 entries each on 32-bit x86. Unused regions need no inner table, but a TLB miss costs more memory reads.
Multithreading model Week 3
The mapping between user threads and kernel threads: many-to-one, one-to-one or many-to-many.
Mutex Week 5
A mutual exclusion lock whose waiting threads sleep instead of spinning, and which only the thread that locked it may unlock.
Mutual exclusion Week 5
The requirement that while one thread is in its critical section, no other thread may be in its critical section.
Mutual exclusion condition Week 7
The deadlock condition that at least one resource can be held by only one thread at a time.

N

Namespace Week 15
A Linux kernel feature that gives a group of processes a private view of one global resource, such as process IDs, mounts, hostname, network or user IDs.
Nested paging Week 15
Hardware support (Intel EPT, AMD NPT) in which the MMU walks both the guest page table and a hypervisor-owned table that maps guest-physical to host-physical addresses. A TLB miss with n guest and m nested levels costs (n + 1)(m + 1) - 1 memory references.
No preemption Week 7
The deadlock condition that a resource can be released only voluntarily by the thread holding it.

O

OOM killer Week 10
The Linux mechanism that runs when reclaim cannot free enough memory. It scores processes, roughly by memory use adjusted by oom_score_adj, and kills the highest scorer to free its pages.
Open file table Week 12
The system-wide table with one entry per open file description, holding the current offset, access mode and reference count, and pointing to an inode. Descriptors made by fork or dup share an entry, while separate open calls get separate entries.
Operating system Week 1
Software that manages a computer's hardware resources on behalf of users and programs and gives them a simpler, uniform interface to those resources.
OPT Week 10
The optimal replacement algorithm (also called MIN), which evicts the page whose next use is farthest in the future. It gives the fewest faults possible but cannot be built because the kernel cannot see the future, so it serves as a yardstick.
Ordered mode Week 13
The default ext4 journaling mode that journals only metadata but writes data blocks to their final place before the metadata commits.
Orphan process Week 2
A running process whose parent has terminated; the kernel reparents it to PID 1 or a subreaper, which reaps it when it ends.
Ostrich algorithm Week 7
The strategy of ignoring deadlock, a reasonable choice when deadlock is rare and prevention or avoidance would slow every request.
Over-provisioning Week 11
Flash capacity that the host cannot see, often 7 to 28 percent of the total, kept as spare room so garbage collection can choose mostly stale blocks and write amplification falls.

P

Page Week 8
A fixed-size block of a process's logical address space. The page size is a power of two, typically 4 KB.
Page cache Week 13
The kernel's in-memory cache of file contents in page-sized frames, shared with the virtual memory system.
Page fault Week 9
A trap raised when a program references a page that is not mapped in memory, asking the kernel to fetch it or, if the access is illegal, to kill the process.
Page replacement Week 10
The policy that chooses a victim frame when a page fault occurs and no frame is free. The victim's page is written to disk first if it is dirty, and the faulting page is loaded into the freed frame.
Page table Week 8
The per-process table that maps each page number to a frame number and holds valid, permission and other bits.
Page-fault frequency Week 10
A thrashing control that measures each process's fault rate against an upper and a lower bound. A process above the upper bound is given a frame, and one below the lower bound loses a frame.
Parallelism Week 3
Several tasks literally executing at the same instant on different cores or processors.
Paravirtualization Week 15
A virtualization technique in which the guest kernel is modified to call the hypervisor explicitly through hypercalls instead of executing sensitive instructions.
Parity Week 11
Redundant information equal to the XOR of the data blocks of a stripe, which allows a lost block to be recomputed from the surviving blocks.
Peterson's algorithm Week 5
A software-only solution to mutual exclusion for two threads using a flag per thread and a shared turn variable, which needs atomics or memory barriers on modern hardware.
Pipe Week 3
A one-way kernel byte stream with a read end and a write end; end-of-file is seen only after every copy of the write end is closed.
Preemptive scheduling Week 4
Scheduling in which the kernel may take the CPU from a running thread, for example on a timer interrupt or when a more urgent thread becomes ready. A non-preemptive scheduler acts only when a thread blocks or exits.
Principle of least privilege Week 14
The rule that every program and user should run with the minimum authority needed for the minimum time.
Priority inheritance Week 5
A cure for priority inversion in which a lock holder temporarily runs at the priority of the highest-priority task waiting for the lock.
Priority inversion Week 5
A problem in which a high-priority task is blocked on a lock held by a low-priority task that a medium-priority task keeps from running.
Privileged instruction Week 1
An instruction that can run only in kernel mode; executing it in user mode raises an exception.
Process Week 2
A program in execution: an address space (text, data, heap, stack), saved CPU state and kernel bookkeeping. One program file can back many processes.
Process control block Week 2
The kernel data structure (PCB, task_struct in Linux) holding a process's PID, state, saved registers, scheduling and memory information, open files and family links.
Process state Week 2
The condition of a process in the five-state model: New, Ready, Running, Waiting (blocked) or Terminated.
Progress Week 5
The requirement that when no thread is in its critical section and some want to enter, the choice of who enters is made only by those threads and cannot be postponed forever.
Proportional allocation Week 10
A frame allocation scheme in which process i receives (size of i / total size of all processes) times the number of frames, never below the architectural minimum. Larger processes get more frames than smaller ones.
Protection domain Week 14
A set of objects and, for each, the operations a process executing in that domain may perform. On Unix it is essentially the user ID, group IDs and capabilities of a process.
pthread_rwlock_t Week 6
The POSIX read-write lock that packages the readers-writers problem, with rdlock, wrlock and unlock operations. The glibc default prefers readers.
Pure demand paging Week 9
Demand paging in which a process starts with no pages in memory and faults in each page as it is first touched.

R

Race condition Week 5
A situation where the result depends on the relative timing of operations by two or more threads, at least one of which writes the shared data.
RAID 5 Week 11
A RAID level that stripes data and rotating parity across N disks, storing N minus 1 disks' worth of data and surviving one disk failure.
Rate-monotonic scheduling Week 4
Fixed-priority real-time scheduling in which a shorter period means higher priority. n periodic tasks are always schedulable if utilization is at most n times (2 to the power 1/n, minus 1).
Readers preference Week 6
A readers-writers solution in which the first reader locks writers out for the whole group and the last reader lets them in again. A steady stream of readers can starve a writer.
Readers-writers problem Week 6
The problem of sharing data among readers, any number of which may overlap, and writers, which need exclusive access. Different solutions decide who is favoured and who may starve.
Ready queue Week 2
The queue of processes in the Ready state that could run immediately and are waiting for a CPU to be assigned by the scheduler.
Redo logging Week 13
A recovery style in which the log holds new values, so recovery replays committed transactions and discards those without a commit block.
Reference bit Week 10
A bit in each page-table entry that the MMU sets to 1 whenever the page is read or written and that the OS clears periodically. It gives a coarse record of whether a page was used recently.
Reference string Week 10
The sequence of page numbers a process touches, used to compare replacement algorithms without real addresses. Only changes of page matter, since repeated references to one page cannot fault.
Resource limit Week 16
A per-process cap on a kernel resource, such as RLIMIT_NOFILE for open descriptors, set with setrlimit and shown by ulimit.
Resource manager Week 1
The role of an OS in allocating the CPU, memory, storage and devices among competing programs while balancing efficiency, fairness and protection.
Resource ordering Week 6
A cure for the dining philosophers deadlock: number the forks and always pick up the lower-numbered one first, so a cycle of waiting cannot form.
Resource-allocation graph Week 7
A graph with thread vertices and resource vertices, request edges from a thread to a resource and assignment edges from a resource to a thread, used to see circular wait.
Response time Week 4
The time from a job's arrival until it first gets the CPU (first run minus arrival), which is the delay an interactive user notices.
Rollback Week 7
Returning a victim process to a safe point after taking a resource from it during recovery. Counting past rollbacks in the victim's cost guards against starvation.
Rotational latency Week 11
The time spent waiting for the wanted sector to rotate under the head. On average it is half a rotation, which is (60 / RPM) / 2 seconds, or 4.17 ms at 7200 RPM.
Round robin Week 4
FCFS with timer preemption: each job runs for at most one time quantum and then goes to the back of the ready queue. It gives good response time but is poor for average waiting time.

S

Safe sequence Week 7
An order of the processes P1 to Pn in which each Pi can finish using the currently free resources plus those released when P1 to P(i-1) finish.
Safe state Week 7
A state in which some order of the processes (a safe sequence) lets each one obtain what it may still need from the free resources plus those released by earlier processes. Unsafe means deadlock is possible, not certain.
Salt Week 14
A random value stored beside a password hash and mixed into it, so identical passwords give different hashes and one precomputed table cannot attack a whole password file.
SCAN Week 11
The elevator disk scheduling algorithm, in which the head sweeps in one direction serving requests until it reaches the end of the disk, then reverses. Every request is served within one round trip, so it avoids starvation.
seccomp Week 14
A Linux facility by which a process irrevocably restricts its own system calls, in practice with a Berkeley Packet Filter program that returns a verdict for each call.
Segmentation Week 8
A memory scheme in which a logical address is a pair of segment number and offset, and a segment table gives each segment a base and a limit. It suits protection and sharing but brings external fragmentation.
Semaphore Week 5
An integer variable changed only by atomic wait and signal operations, with a queue of blocked threads; it is used for locking, signalling and counting resources.
Sensitive instruction Week 15
An instruction that reads or changes machine configuration or behaves differently depending on it. Trap-and-emulate works when every sensitive instruction is also privileged, which the original x86 did not satisfy.
setuid Week 14
A mode bit (octal 4000) that makes a new process run with the effective user ID of the file's owner while its real user ID remains the caller's.
Shared memory Week 3
An IPC method where the kernel maps the same physical pages into several processes, which then communicate by reading and writing memory directly.
Signal Week 3
A small asynchronous notification sent to a process, such as SIGINT or SIGTERM, handled by a default action, by ignoring it or by a handler function.
SJF Week 4
Shortest-job-first scheduling, which runs the ready job with the shortest next CPU burst. It gives the lowest average waiting time among non-preemptive schedulers but can starve long jobs.
Slab allocator Week 9
A kernel allocator that keeps a cache per object type, made of slabs of equal-sized slots, so small objects are allocated quickly and reused still initialized.
Small-write penalty Week 11
The extra cost of updating parity-based RAID. A small write to RAID 5 needs two reads and two writes (new parity = old parity XOR old data XOR new data), four disk I/Os for one logical write.
Spinlock Week 5
A lock whose waiting threads loop on an atomic instruction until it is free, which suits very short waits on multicore machines but wastes CPU otherwise.
SRTF Week 4
Shortest-remaining-time-first, the preemptive form of SJF. A newly arrived job preempts the running one if its burst is shorter than the running job's remaining time.
SSTF Week 11
Shortest seek time first disk scheduling, which always serves the request closest to the head. It cuts head movement sharply but can starve distant requests.
Stack algorithm Week 10
A replacement algorithm for which the set of resident pages with n frames is always a subset of the set with n + 1 frames. Such an algorithm cannot show Belady's anomaly; LRU and OPT are stack algorithms and FIFO is not.
Stack canary Week 14
A random value placed between a function's local arrays and its saved return address and checked before returning, so a contiguous overflow is detected and the program aborts.
Stateless server Week 13
A server, as in NFS versions 2 and 3, that remembers nothing about clients between requests, so each request is self-contained and idempotent and a crashed server needs no recovery.
Sticky bit Week 14
A mode bit (octal 1000) on a directory that lets only a file's owner, the directory's owner or root delete or rename entries, as on /tmp.
Stress test Week 16
A test that runs a program many times or under heavy load, on several cores, to make rare timing-dependent failures such as races and deadlocks appear.
Striping Week 11
Splitting data into fixed-size stripe units placed round-robin across several disks, so large reads and writes run on all disks in parallel.
Symbolic link Week 12
A file whose content is a path string that the kernel substitutes during path resolution. It can cross file systems and point to directories, and it dangles if its target is removed.
System call Week 1
The controlled entry into the kernel, a deliberate trap through which a program requests a privileged service such as opening a file.

T

Test-and-set Week 5
An atomic hardware instruction that writes 1 into a word and returns the old value, which is enough to build a lock.
Text segment Week 2
The read-only, executable region of a process that holds its machine instructions; it can be shared among processes running the same program.
Thrashing Week 10
A state in which a process spends more time servicing page faults than executing, or a system in which many processes do so at once. It can arise when the OS admits more processes because CPU utilization has dropped.
Thread Week 3
A single flow of control inside a process with its own program counter, registers and stack, sharing the process's code, globals, heap and open files.
Thread-local storage Week 3
Variables declared so that each thread has its own private copy, such as errno or a variable marked __thread.
ThreadSanitizer Week 16
A compiler-based tool, enabled with -fsanitize=thread, that instruments memory accesses at run time and reports data races together with the stacks of both conflicting accesses.
Time slice Week 2
The maximum interval a process may run before a timer interrupt returns it to the Ready state; also called a quantum.
Timer Week 1
A hardware clock that only the kernel can program, which interrupts the CPU after a set interval so the kernel always regains control.
TLB reach Week 9
The amount of memory covered by the TLB, equal to the number of TLB entries times the page size.
TOCTOU race Week 14
A time-of-check to time-of-use race: a program checks a condition on a name and later acts on it, but another process changes what the name refers to in between.
Transaction commit Week 13
The point at which a journal transaction becomes durable, marked by writing the commit block (TxE) after the logged blocks have completed.
Translation look-aside buffer Week 8
A small, fast hardware cache of recent page-to-frame translations. A hit gives the frame at once, and a miss requires a page table walk.
Trap Week 1
A synchronous transfer of control into the kernel caused deliberately by the running program, for example by a system call instruction.
Trap-and-emulate Week 15
A virtualization technique in which the guest kernel runs deprivileged, each privileged instruction traps into the hypervisor, and the hypervisor emulates it on the guest's virtual state.
TRIM Week 11
A command (called deallocate on NVMe) by which the file system tells an SSD which logical blocks are free, so the FTL does not copy deleted data during garbage collection.
Turnaround time Week 4
The time from a job's arrival to its completion (completion minus arrival).
Type 1 hypervisor Week 15
A hypervisor that runs directly on the hardware as the most privileged software, such as Xen, VMware ESXi or Hyper-V.
Type 2 hypervisor Week 15
A hypervisor that runs as an ordinary application on a host operating system, such as VirtualBox.

U

umask Week 14
A per-process mask that removes permission bits from every requested file mode: mode given = mode requested AND NOT umask.
Unix mode Week 14
The 12-bit permission field of a file: read, write and execute bits for owner, group and other, plus the setuid, setgid and sticky bits, usually written in octal.
Use-after-free Week 16
A bug in which a program reads or writes heap memory after it has been released with free, which can corrupt the allocator and other data.
User-level thread Week 3
A thread managed by a library in user space without kernel knowledge; switching is cheap but one blocking call blocks the whole process.

V

Valgrind Week 16
A tool that runs a program on a simulated CPU without recompilation to detect memory errors and leaks (with --leak-check=full) and, through Helgrind, data races, at a large slowdown.
Valid/invalid bit Week 9
A page-table entry bit showing whether a page is legal and resident in memory (valid) or not (invalid); an invalid reference causes a page fault.
Virtual File System Week 12
A kernel layer of generic file objects and per-file-system function tables, so the same open, read and write calls work on ext4, FAT, NFS and virtual file systems alike.
Virtual File System (VFS) Week 13
The kernel layer that gives every file system the same interface through generic superblock, inode, dentry and file objects with per-file-system operation tables.
Virtual memory Week 9
A technique that separates the logical address space seen by a program from physical memory, so only part of a program needs to be resident in RAM.
Virtual runtime Week 4
In Linux CFS, the per-task counter that advances while the task runs, more slowly for heavier tasks (vruntime increases by delta times 1024 divided by weight). CFS always runs the task with the smallest value.
VM exit Week 15
A hardware-assisted switch from a running guest back to the hypervisor, triggered by an event the hypervisor has chosen to intercept. A VM entry resumes the guest.

W

wait Week 2
The system call by which a parent blocks until a child terminates and collects its exit status, allowing the kernel to discard the child's PCB.
Wait-for graph Week 7
The graph obtained from a single-instance resource-allocation graph by deleting resource nodes, where an edge Ti to Tj means Ti waits for a resource held by Tj. A deadlock exists exactly when it has a cycle.
Waiting time Week 4
The time a job spends in the ready queue, equal to turnaround time minus its CPU burst for a job that does no I/O.
Wear leveling Week 11
Spreading erases evenly over flash blocks so no block reaches its limited program and erase cycles early. Static wear leveling also moves rarely changed data off young blocks.
Working set Week 9
The set of pages a process is actively using; once it is resident the program runs with few faults.
Worst fit Week 8
A hole-selection policy that takes the largest hole, hoping the leftover is still useful. It is usually worse than first fit or best fit.
Write amplification Week 11
The ratio of data written to flash to data written by the host. A value of 1 is ideal, and garbage collection copying pushes it above 1, especially when the drive is nearly full.
Write-back Week 13
A cache policy that updates only memory, marks the page dirty and writes it to disk later, which is fast but loses data if the system crashes first.
Writer starvation Week 6
The situation in which a writer waits indefinitely because overlapping readers keep the reader count above zero. The writers-preference variant avoids it but can starve readers.

X

xv6 Week 16
A small Unix-like teaching kernel for RISC-V, written at MIT as a re-implementation of Sixth Edition Unix, short enough to read in full.

Z

Zero-fill-on-demand Week 9
Giving a process fresh anonymous memory by mapping untouched pages to a shared zero page and allocating a zeroed frame only on first write.
Zombie process Week 2
A terminated process whose parent has not yet called wait, so only its PCB entry (PID and exit status) remains.
